# Sample game visual audit

Baseline at `b8bace5` plus the existing working tree. The 54 scene JSON files in `assets/samples` match the 54 gallery entries. The gallery includes games, terrain walkthroughs and technical demonstrations. Its labels describe templates. The scene genre and components determine profile behavior.

The gallery has no strategy template. Isometric RPG is represented by the 2.5D Action RPG courtyard. Desktop is the authoring target. `engine-web` is in the Gradle build, and the JavaScript Babylon player/editor code lives separately. Web importer, physics and scripting support vary by scene. See the [backend matrix](../BACKEND_SUPPORT_MATRIX.md).

## Playable baselines and visual gaps

- **2D Platformer and Tiles variant.** Rectangle player, shape pickups and goal, Java movement and following camera. The original collides against boxes and the variant uses editable tile data. Both have four SFX sources and music. Sprite art can be replaced independently of collision. There are no enemy encounters or combat animations.
- **Pixel Adventure and Sprite 2.5D.** Animated pixel hero and coins, tile collision and scripted movement. The 2.5D scene uses depth-layered primitive scenery and directional lighting. Expand the existing pixel art direction and keep its collision plane.
- **Profile platformers.** Runner or Jumper is a primitive on a Jolt character controller, with a profile camera and movement. The terrain version uses a native heightfield, while the other courses use boxed platforms. They lack animated player models, enemies and authored audio.
- **Action RPG.** Valley has a red box hero, native terrain and simple static colliders. The courtyard places a primitive hero at a spawn point among boxed walls and pillars. Both have a Player and Jolt character controller, scene camera and profile controls. Neither scene authors a rig, combat clips, enemies, weapons, damage, health UI or audio.
- **Racing.** Arcade script drives the player and two rivals, reads road segments by name and reports laps and position. Cars, road and scenery are assembled from primitives. A chase camera, three synthesized engines, four cues and music are present. Replace visible geometry without changing the road entities the race logic reads.
- **Shooter and ranges.** The 2D ship and enemies use shapes. Arena FPS has a primitive weapon and pooled drones/projectiles. The first-person profile range uses pushable Jolt crates. Preserve crosshair visibility and input bindings while improving visual surfaces.
- **Side-scrolling action.** Ruins Runner, Grapple Gorge, Three Heroes and Fighter use colored 3D geometry with scripted movement and camera or fixed framing. Existing interactions include moving platforms, grapple, character abilities and timing-based fighting. Fighters have primitive bodies. Their attacks are gameplay states rather than skinned animation clips.
- **Arcade and sandbox.** Breakout uses flat paddle, ball and bricks. Collector rolls a ball and Runner navigates pooled obstacles. Hopper is a box-based jumping course. Puzzle has scripted grid levels and primitive crates. Blockworld and Obby intentionally use block silhouettes. Materials can improve those scenes while retaining readable gameplay shapes.
- **Landscapes and showcases.** The original biomes use generated glTF geometry. Terrain versions expose editable heightfields. The CC0 valley already places licensed prefab scenery with simple collision. Physics visuals, bones, and sample clips often use primitives to expose the systems being demonstrated. Character Creator shows three baked humanoid models. Keep technical reference scenes legible.

## Rendering, import and performance baseline

Desktop renders glTF/GLB with gdx-gltf PBR, supports skinned animation, and uses native material and terrain assets. Terrain chunks have LOD and view culling. Existing LOW, MEDIUM and HIGH presets tune shadow and environment map resolution. ULTRA, general mesh LOD and texture-compression parity need evidence before they can be claimed. Models can be linked through scene and prefab references. FBX and Blender files require an external conversion workflow. The bundled editable static mesh work is in progress in the existing working tree.

The sample README contains older collision, audio and packaging statements. Current scene data includes Jolt controllers, Box2D bodies, music components, graph scripts, and a packaged editor/runtime workflow. The live files and current tests take precedence.

Scene component counts are not performance measurements. For historic desktop medians see [performance baselines](../PERFORMANCE_BASELINES.md) and [terrain LOD](../reports/m3-8-terrain-level-of-detail.md). Current audit did not visually inspect these scenes or generate new frame timings.

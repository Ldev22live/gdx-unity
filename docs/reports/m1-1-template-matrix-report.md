**Date:** 2026-11-14. **Platform:** Windows 11 Pro, Java 21.

## Done-when and result

The chart's done-when for M1.1 is: *the matrix lists every sample and domain; the audit passes for every sample that does not depend on R2 to R4.*

- **First half: met.** The matrix exists, is generated by a test, and lists all 40 sample scenes against 11 editing domains.
- **Second half: not met, and this is the finding.** 27 of the 40 samples have at least one FAIL, and most of those causes do not depend on R2 to R4: **19 samples keep their logic as Java source** (milestone M1.2). The audit's job is to show this, and it does. "The audit passes" for those samples will be true when M1.2 has converted them.

So M1.1 delivered the instrument and its first reading. It did not make the samples editable.

## What was built

`TemplateMatrix` (`editor-desktop/.../audit/`, beside the existing `EditabilityAudit`) judges each sample scene on the domains of roadmap Appendix F2 that a scene file can show, by rules written out in its Javadoc:

| Domain | Used when | PASS | FAIL |
|---|---|---|---|
| World | always | every component has a Details editor, every named file exists | either is not true |
| Terrain | a Terrain component, or a glTF whose name says it is the ground | the `.terrain` file exists | the ground is a baked model |
| 3D models | a glTF model that is not the ground, or a sculpt | a sculpt (it has an editor) | a glTF model: there is no mesh editor |
| 2D art | sprite renderer, sprite animator or tilemap | `.sprite` files that exist | a flattened PNG or JPEG, or a missing file |
| Logic | scripts or graphs | graphs only | any behaviour is Java source |
| Animation | an Animator, a sprite animator or a model with an animation | `.anim` clips and `.sprite` files that exist | a clip baked into the glTF, or a missing file |
| Materials, light | a material file or a light | (both have Details editors) | none |
| Sound effects | an Audio Source or Engine Sound | a synthesized cue | a recorded WAV or OGG (no waveform editor) |
| Music | a Music Source | its `.song` exists | it does not |
| UI text | a Text component | (data, edited in Details) | none |
| Gameplay, physics | physics, a character controller or scripts | unless the rules are Java source | the rules are Java source |

A missing editor, a missing source or hardcoded behaviour is a **FAIL, never "not applicable"** (Appendix F5). Each sample also gets a label: "Technical Demo / Partially Editable" if any used domain fails, otherwise "Candidate: domains pass, gates pending". **No sample can be called Fully Customizable**, because the Appendix F5 checks that nothing automates yet have not been made for any sample: that a user's edit succeeds, undo and redo of it, Play and Stop of the edited sample, export and launch per sample, a license manifest for the sample's assets, and the desktop visual and listening checks. These are listed in `TemplateMatrix.UNCHECKED_GATES` and in the matrix section.

The table lives in [FEATURE_TEST_MATRIX.md](../FEATURE_TEST_MATRIX.md) (section "Sample-to-template matrix") between markers; `TemplateMatrixTest` regenerates it (`GDXUNITY_UPDATE_AUDIT=1`) and **fails when it is stale**, the same way the existing editability audit does.

## Tests

`TemplateMatrixTest` (12 tests, new):

- One test per rule on a small scene written for it: Java logic fails Logic and Gameplay, graphs pass, no logic is n/a; a defect fails World; a baked ground fails Terrain and a `.terrain` passes (a missing file fails); a glTF fails 3D models and a sculpt passes; a flattened PNG and a missing sprite fail 2D art while `.sprite` passes; a baked clip and a missing clip fail Animation; a synthesized cue passes and a recorded clip fails; a song passes and a missing song fails.
- A sample is never labelled Fully Customizable while the gates stand; a failing sample is labelled Technical Demo; every entry has a result for every domain.
- On the real samples: the samples that fail Logic are exactly the ones the existing audit lists as Java source, every sample passes World, the five landscape scenes fail Terrain and `terrain-3d` passes.
- The table in the matrix is up to date.

Did these fail without the change? The test class calls a class that did not exist, so none could have passed before. The rules were not run against a mutated rule set to show each assertion bites; each rule's test asserts the evidence text as well as the status.

## Limits

- **The rules are mine and are written out.** Anyone may disagree: for example, "a glTF model fails 3D models" holds today because there is no mesh editor, and will change with R7a; "a synthesized cue passes" assumes the Details editor and sfxr suffice.
- **The matrix reads scene files, not runtime behaviour.** A game that draws its interface in script code is not seen in the UI column; a graph is counted PASS without being validated (graph validation is a separate check in Appendix F5 that this milestone did not add).
- **License:** no sample has a license manifest, so that gate cannot pass for any of them. It is listed, not scored per sample, so as not to print 40 identical failures.
- **Packaging** is not a column for the same reason (a gate, not a property of a scene file).
- Not examined: other asset sources besides the sample scenes (the Content Browser's own assets, templates that do not exist yet).

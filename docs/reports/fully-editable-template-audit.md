# Fully Editable Template Audit

Roadmap MT.8 (Appendix F5 and F7). **Date:** 2026-11-18. **Milestone report:** [mt-8-template-audit.md](mt-8-template-audit.md).

The three tables are generated by `TemplateAudit` (`editor-desktop/.../audit`) and kept current by `TemplateAuditTest`, which fails when a table is stale. Refresh them with `GDXUNITY_UPDATE_AUDIT=1 ./gradlew :editor-desktop:test --tests "*TemplateAuditTest"`. Everything else in this file is written by hand.

Existing samples are preserved: this audit changes no sample, graph or engine code. Nothing here claims a feature that is not there:
- a gate that nothing has checked is **BLOCKED**, never PASS;
- a missing editor or behaviour that lives only in Java is **FAIL**, never N/A (F5).

## 1. The verdict

- **No sample is Fully Customizable**, and none can be called that yet. Every sample has four BLOCKED gates:
  - a person's edit with undo and redo in each domain;
  - launching the exported game;
  - a licence record for project-made assets;
  - observed graphics and sound.
- **What already holds for all 45 samples:**
  - every reference resolves and every component has a Details editor;
  - every scene saves and reopens unchanged;
  - every scene plays without errors;
  - every scene becomes a separate project that exports.
- **The FAILs come from three causes:**
  - **Java-only logic** in 20 samples. This is the largest gap, and its fix is M1.2's graph conversions.
  - **Baked content with no editable replacement** in 7 samples: five landscapes and the mesh-collider sample with glTF grounds, and the character creator's clips baked into glTF.
  - **glTF props with no mesh editor** in the samples that place them. They pass the "baked" gate only through the sculpt-a-copy workflow.
- **Every one of the 20 graphs loads and validates.**
  - Five re-create their Java script completely, each with a test that compares them.
  - Ten cover only part of their script, and none of those ten is run by a sample.
  - Five are graphs of their own.

## 4. Staged migration plan

The stages follow the gates that fail, in order of how many samples each unblocks. Each stage keeps the originals: a migrated version is written beside the original, as MP.3 did. The shipped samples are opened read-only (R1).

| Stage | What | Unblocks | Depends on | Needs |
|---|---|---|---|---|
| 1 | Finish the graph conversions: the nodes the 10 partial graphs need (collision boxes, scores, spawning), then switch each sample to its graph once a parity test passes | "No hardcoded-only logic" for up to 20 samples | M1.2 | None beyond M1.2's plan; 5 of 15 are done |
| 2 | Landscapes to `.terrain`: convert the five baked glTF grounds and the mesh-collider ground to native terrain, keeping the props | "Source present" and "No baked-only content" for 6 samples | M3.10 (M3.6 scatter for trees) | Terrain import from a height function or mesh: TD below |
| 3 | Character clips: export the clips baked into the creator's glTF as `.anim` clips the Timeline edits | `character-creator-3d` | R5 | — |
| 4 | Mesh editing of glTF props (houses, rocks, trees) | "Editors open: 3D models" for the glTF samples | R7a (M7a.1 to M7a.5) | TD-gated in the chart |
| 5 | Licence record: an asset licence for project-made content, plus a per-asset manifest | "Licence verified" for all | the owner | TD below |
| 6 | Per-sample checks: automate edit, undo and redo per domain on each template; launch each exported template; then a person signs off the graphics and sound | the last three BLOCKED gates | MT.9 golden journeys | A person for the observed checks |

The reference templates MT.1 to MT.5 come after stages 1 to 5 for the samples they build on. A template is offered as **Fully Customizable** only when its row has no FAIL and no BLOCKED (M1.7 already enforces the label).

## 5. Decisions needed (proposals for the owner; not recorded as TDs)

1. **Asset licence policy.** Should project-made content be released under CC0, Apache 2.0, or something else? Should every shipped asset carry a manifest entry (A3's fields)? Nothing can pass "Licence verified" until this is decided.
2. **Template versioning.** A project made from a template should record the template id and version, so that later sample migrations can offer an update without touching the user's edits (F4).
3. **Converting baked grounds to terrain** (stage 2). Should a glTF ground be resampled into a `.terrain` heightmap (lossy at overhangs, which these grounds do not have), or should the ground be regenerated from the generator's height function (exact, but only for generated grounds)? This needs a TD under TD-082.
4. **When a sample switches from Java to its graph** (stage 1). Should the Java script stay beside the graph as reference, or be removed? Should the web port follow?

## 2. What was built

- **`engine-scene`:** `GameGenres.actionRpg3D` and its playable entry, with named constants for the camera (distance 520, pivot height 90, tilt 18 degrees) and the movement (walk 400 units per second, jump 600, about 1.8 m, turn 720 degrees per second). Action RPG + 2.5D stays planned (M3c.3).
- **`engine-render` `play`:**
  - `GroundWalkMover` (new, runtime only): walks relative to the yaw of the active game camera, so it also works with an author's own rig; faces where it walks; one jump per press. `walkDirection` and `turnToward` are public and tested on their own.
  - `ProfileCameraRig`: the `THIRD_PERSON` kind (it used to throw). It now takes the profile's key mapping and the input source, because the rig reads the turn keys itself.
  - `PlayProfiles.apply` adds the walker (it used to throw for `GROUND_WALK`).
- **Sample `action-rpg-valley-3d.json`** (from `tools/make_profile_samples.py`, which now writes both profile samples):
  - the terrain sample's valley (`terrains/Valley.terrain`) with its Terrain Collider 3D;
  - a boulder and a crate with Box Collider 3D;
  - Hero with a Character Controller 3D and a Player, where the terrain sample puts it;
  - a camera with no rig; Game Mode 3D, Game Genre Action RPG;
  - **no scripts and no graphs**.
  - It is in the template gallery (desktop only, with a preview) and in the web test's list of known unsupported components.
  - `terrain-3d.json` is unchanged: it is still walked by its graph.
- The platformer sample, regenerated by the same tool, came out byte-identical.
